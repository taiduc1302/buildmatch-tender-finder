# Contributing

Use an issue-first workflow for meaningful changes:

1. Open a Bug report or Feature request with reproducible evidence and acceptance criteria.
2. Create a focused branch for the issue.
3. Open a pull request that links the issue (`Closes #...` when appropriate).
4. Record tests or other validation evidence in the PR.
5. Ask reviewers to focus on the riskiest assumptions or edge cases before merge.

Keep changes small enough to review. Do not include secrets, credentials, private tender documents, customer data, or other confidential material in issues, commits, logs, screenshots, or test fixtures.

Trivial typo-only edits may skip an issue when the reason and validation are obvious.

# DECISIONS — configurable company profile and keywords

Date: 2026-07-14

1. `config/keywords.xlsx` is the canonical editable rule source for the three migrated surfaces. A successfully validated canonical workbook is atomically copied to an external SHA-verified last-known-good workbook. If the normal canonical path later becomes missing or invalid, only that verified snapshot may be used and its use is visible in the GUI, validation report, and run manifest. There is no hardcoded-rule fallback. A custom override path does not implicitly borrow the canonical snapshot.
2. The six requested `Keywords` columns are retained and one minimal extension, `param`, is added. `gate_collision` rows use it for pipe-separated collision text; `gate_exclude` rows use `negative_title` or `absolute_title`. This preserves the existing structured gates instead of flattening them.
3. `tender_match` is added to the category vocabulary because the existing tender detector is a separate verbatim regex surface and does not fit the proposed civil-gate categories.
4. Existing matching semantics are preserved per surface:
   - fit score, civil include/exclude/weak/collision, user-facing civil labels, and both Vancouver lists use case-insensitive substring matching (historically lowercase plus `in`);
   - tender-language and reference patterns are copied verbatim as regex rows and searched against lowercase text;
   - collision terms are stripped globally before the civil include check, matching the prior implementation;
   - a negative title gate is overridden only by a civil title hit not listed in `gate_weak`; `absolute_title` is never overridden.
5. `exact` is defined for new customer rules as trimmed, case-insensitive whole-field equality. It did not exist in the migrated Meridian surfaces, so no pre-filled Meridian row uses it.
6. Profile values are generated as `contains` rules with the requested defaults: regions geography/+8, work types positive/+9, and known clients client/+6. An explicit `Keywords` row replaces the generated row with the same case-insensitive `(keyword, category)` key, so `active = N` can disable a Profile default.
7. Positive and negative rules apply every matched row once. Geography and client remain one-time bonuses; if a future custom file gives matching rows different weights, the highest matching weight is used. All current Meridian rows have uniform +8/+6 values, so this adds configurability without changing baseline behavior.
8. The live profile requires `company_name`. The deliberately blank handoff template is validated with the loader's explicit `allow_empty_profile=True` mode; all other schema, dropdown, regex, duplicate, and type rules still apply.
9. The cache is keyed by resolved workbook path for the life of a run, so an Excel save midway through scoring cannot mix two rule versions. CLI startup and the GUI Validate/run actions use an explicit force reload. Effective rules are stably sorted by category, normalized keyword, param, and source.
10. `TENDER_FINDER_KEYWORDS_CONFIG` is supported only as a path override for isolated tests/portable invocation. The normal path comes from `tenderfinder_package_paths.py` and resolves to package-local `config/keywords.xlsx`.
11. The Dashboard header is the only output label changed to include `company_name`; output filenames, sheet names, columns, score cap, and tier thresholds remain unchanged.
12. `tenderfinder_agent2.py` remains frozen and independent as required. It now declares that limitation in its module docstring and at startup.
13. The founder decision is `RESCORE_ALWAYS`: every main-pipeline run treats stored review-workbook scores as audit-only prior values and recomputes keyword-derived score, signal tier, labels, and score-based Future Projects routing from the current workbook. The unified replay seam is `normalized_row`; fresh raw records also score in `normalize_lead`, so both collection and replay use the same scorer.
14. The score-based Future Projects replay gate is 50, matching the existing boundary between actionable MEDIUM/HIGH and LOW signal quality for non-Vancouver records. A record that falls below this gate moves to `Run_Queue`, is named in the run log/build report with old/new score and threshold, and is not silently discarded. Non-score connector classifications (`Bulk_Intake_Raw`, `Rejected_Archive`, and unrelated Run Queue holds) are not promoted merely because a keyword score changes.
15. Previously tracked Outreach rows survive even when the current keyword configuration moves their underlying tender/lead out of the actionable set. User-owned status, dates, notes, contact, and identifying fields are preserved by stable ID; the current tier is shown as `BELOW_CURRENT_GATE`.
16. `exact` rules are evaluated against each preserved business field while `contains` and `regex` rules retain concatenated-text behavior. This makes an exact full-title rule usable without changing the workbook schema or historical substring semantics.
17. The rule cache remains per process/run. A new process, GUI Validate/run action, or explicit force reload reads the edited workbook; one invocation never mixes rule versions midway through scoring.
18. Three honest exceptions remain: `tenderfinder_agent2.py` is frozen legacy code; historical Vancouver permit rows do not persist the raw attributes required to recreate `_van_permit_fit_tier`, so only that stored non-score tier is retained during replay; tender candidates that were never persisted cannot be retroactively evaluated, while every newly parsed candidate uses current tender/civil rules.
19. Historical packaged scores such as 74, 81, and 65 came from the snapshot-era replay behavior that copied `fit_score` in `normalized_row`. They are deliberately not preserved as expected values after `RESCORE_ALWAYS`.
20. Offline end-to-end variants are authored outside the repository from temporary copies of the canonical/template workbooks. `TENDER_FINDER_KEYWORDS_CONFIG` selects each variant for one invocation and is cleared afterward. Validation reports, the last-known-good workbook, and its metadata are mutable runtime state under `C:\tenderfinder_out\state\<context>\settings`, never package-local artifacts.
21. Editable regex is bounded by pattern length, input length, prohibited-construct validation, and a runtime timeout. A rejected or timed-out regex is a visible validation/run error and cannot silently fall back to a built-in expression.
22. Non-Vancouver signal tiers are recomputed from current score on replay. Vancouver permit tiers are recomputed only when the persisted raw snapshot is sufficient; otherwise the retained legacy tier is explicit in `Keyword_Change_Audit`. This prevents an old permit tier from being presented as a current keyword-derived result.
